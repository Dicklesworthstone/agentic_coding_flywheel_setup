# What is EE?

Ever wished your coding agent remembered the hard-won lessons from last week instead of repeating the same mistakes? EE gives agents a durable memory.

**EE (Eidetic Engine)** is local-first durable memory for coding agents. It stores typed memories (rules, decisions, failures, commands, conventions) and retrieves them with hybrid BM25 + local vector search that produces explainable scores. Everything runs locally, with no cloud dependency and no API keys.

---

# Checking Installation

Verify EE is installed:

```bash
ee --version
```

---

# Setting Up a Project

EE keeps one store per project. Create it once, from the project directory:

```bash
cd /data/projects/myproject
ee init --workspace . --force --skip-boilerplate
```

`--force` is needed when the project already has an `AGENTS.md`; EE leaves that
file unchanged. `--skip-boilerplate` stops it from writing a `CLAUDE.md`. Add
`.ee/` to the project's `.gitignore`: it holds the local database and keys.

---

# Building a Context Pack

Before starting a task, ask EE for the relevant memories:

```bash
ee pack "refactor the auth middleware"
```

This builds a token-budgeted context pack of the most relevant rules, decisions, and past failures. The `eectx` alias does the same thing.

---

# Capturing and Finding Memories

Store a rule when you learn something worth keeping:

```bash
ee remember "Always run migrations before seeding the test database"
```

Search prior memories, and ask why a specific memory was stored or selected
(memory IDs appear in `ee search` results):

```bash
ee search "database migrations"
ee why <memory-id>
```

---

# Why EE Matters for Agents

Agents forget everything between sessions. EE provides:

- Durable rules and conventions that survive context resets
- Explainable retrieval, so you can audit why a memory was chosen
- `ee import cass` to make your cass session history searchable evidence
- `ee preflight check --cmd "..."` advisory risk lookup before dangerous commands

---

# EE and CM

CM, the memory tool every ACFS install has, builds a playbook from your agent
sessions (`cm reflect`) and serves it with `cm context`. Keep using it. EE is for
lessons you record on purpose in one project: decisions, failures, commands,
conventions. Run `ee pack` alongside `cm context` before a task, and put each
lesson in one tool, not both.

---

# Common Scenarios

```bash
# Review curation candidates (distilling raw memories into rules)
ee curate candidates

# Import past agent sessions as evidence (ee must first be told where
# cass is installed; the guide linked below shows how)
ee import cass

# Check EE health (JSON works on nearly all commands)
ee doctor --json
```

# Summary

You've learned:
1. **ee pack** - Build a token-budgeted context pack for a task
2. **ee remember / ee search / ee why** - Capture, find, and explain memories
3. **ee curate candidates** - Review proposals that distill raw memories into rules
4. How local-first memory keeps agents from repeating old mistakes
