# What is EE?

Ever wished your coding agent remembered the hard-won lessons from last week instead of repeating the same mistakes? EE gives agents a durable memory.

**EE (Eidetic Engine)** is local-first durable memory for coding agents. It stores typed memories (rules, decisions, failures, commands, conventions) and retrieves them with hybrid BM25 + local vector search that produces explainable scores. Everything runs locally — no cloud, no API keys.

---

# Checking Installation

Verify EE is installed:

```bash
ee --version
```

---

# Building a Context Pack

Before starting a task, ask EE for the relevant memories:

```bash
ee pack "refactor the auth middleware"
```

This builds a token-budgeted context pack of the most relevant rules, decisions, and past failures. The `eectx` alias does the same thing.

---

# Capturing and Finding Memories

Store a rule when you learn something worth keeping:

```bash
ee remember "Always run migrations before seeding the test database"
```

Search prior memories, and ask why a specific memory was stored or selected
(memory IDs appear in `ee search` results):

```bash
ee search "database migrations"
ee why <memory-id>
```

---

# Why EE Matters for Agents

Agents forget everything between sessions. EE provides:

- Durable rules and conventions that survive context resets
- Explainable retrieval, so you can audit why a memory was chosen
- `ee import cass` to mine your cass session history for memories
- `ee preflight check --cmd "..."` advisory risk lookup before dangerous commands

---

# Common Scenarios

```bash
# Review curation candidates (distilling raw memories into rules)
ee curate candidates

# Mine past agent sessions for memories
ee import cass

# Check EE health (JSON works on nearly all commands)
ee doctor --json
```
